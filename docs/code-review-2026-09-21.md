## Verified defects fixed

| Severity | Finding and consequence | Fix and evidence |
| --- | --- | --- |
| P1 | Logout/device revocation left refresh tokens usable, allowing a revoked session to acquire new access tokens. | Revoke both credentials transactionally. Real PKCE token-exchange tests assert `invalid_grant` after revocation and preserve another device's session. |
| P1 | Account deletion removed only the user, retaining account-associated records and leaving ownerless households. | Atomic deletion action cleans sole-member households, credentials, sessions, reset tokens and invitations; transfers ownership where needed; erases/scrubs attributed shared resources while preserving sync tombstones. Tests include remembered sessions and mobile-created resources. |
| P1 | Mobile-created resources were not attributed to their author, so deletion cleanup could not identify them. | Server assigns authenticated creators to REST/sync resources and tracks field contributors, including children and ingredients. Generated copies inherit provenance. Client-supplied authorship is not trusted. |
| P1 | Shared contributions survived account deletion, and stale offline edits could restore erased text. | Scrub attributed fields, erase created resources, and preserve minimal tombstones. Server row/cursor erasure guards and mobile canonical replacement handle in-flight edits and queued chunks; unrelated fields remain. PostgreSQL testing caught numeric JSON-key ambiguity; nonnumeric contributor keys now work on both engines. |
| P1 | A queued sync write could pass middleware authorization before membership removal and run after deletion. | Recheck membership while holding the household write lock. Regression covers revoked membership. |
| P1 | Timestamp truncation let an older edit within the same second overwrite a newer edit. | Microsecond storage/serialization plus a forward schema migration. The added regression failed before the fix. |
| P1 | Sync identity lookups assumed child tables had a household column, producing server errors on PostgreSQL. | Use each resource’s household-scoped query for identity and live-parent maps. The existing sync suite now passes on PostgreSQL 18. |
| P1 | Malformed UUIDs reached PostgreSQL UUID queries before validation and could abort an entire batch. | Validate before prefetch and reject individual bad rows. |
| P1 | New/restored child records could reference deleted parents. | Resolve foreign keys against live parents; detach retained shopping lists when their source plan is deleted. Regression covers same-batch and later-batch cases. |
| P1 | Late token refresh and API/sync responses could outlive sign-out or account changes. | Session/connection generations reject obsolete responses; credential persistence is serialized and account query caches cleared. Tokens migrate to one atomic Keychain value, with a signed-out marker preventing legacy credentials from reappearing after interrupted cleanup. Concurrent refresh, offline failure and account-change regressions added. |
| P1 | Remote household changes could erase pending local edits. | Preserve pending data and refuse destructive rebinding; allow switching back to the bound household to upload it. |
| P1 | Expired refresh credentials could leave a session stuck, while transient retry failures incorrectly signed users out. | Distinguish invalid credentials from connectivity/server/validation failures; test both proactive and reactive refresh. |
| P2 | Email verification was configured but the User model did not implement the verification contract. | Enable the contract, prove mail dispatch, and require verified email for invitation responses. Preserve OAuth registration redirects and permit unverified account deletion. |
| P2 | Stale route-bound invitations could override revocation or an earlier response. | Re-fetch under database locks and validate fresh state. |
| P2 | The sync debounce defeated retry backoff. | Respect pending retry timers and test that failed requests do not immediately repeat. |
| P2 | Concurrent settings mutations could reach the server out of order. | Serialize settings mutations; replace the inaccurate automatic-retry promise with explicit retry guidance. |
| P2 | Release config could retain a generated native project's development HTTP exceptions. | Explicitly override ATS in release configuration; inspected production config contains no exception domains. |
| P2 | CI lint jobs silently fixed files instead of rejecting regressions; mobile had no CI workflow. | Add/check deterministic installs, type checks, linting, tests and mobile export; fix PHP matrix and root platform requirement. |

- Align React and native libraries with the installed Expo 57 compatibility map. The previous versions were newer than the SDK-supported set, which was not a safe production combination.
- Update npm/Composer packages within the applications' supported constraints. Known advisory counts went from 14 moderate affected packages in mobile and 8 affected packages in web tooling (including critical advisories) to **zero reported**. Composer also reports zero advisories. Registry audits are a dated check, not a guarantee against unknown vulnerabilities.
- Update the vulnerable URL parser and Xcode UUID dependency. The URL parser's modern module interface differs from Expo Router's namespace imports: a small source patch preserves named exports, with runtime parse/stringify regressions. Package patch failures now fail installation.
- Clean `npm ci` installs were exercised. Repaired incomplete optional dependency lock entries in the web repository.
- Deliberately did not force unrelated breaking major upgrades or downgrade Legend-State v3 beta to npm's older stable v2 tag. The app depends on v3 behavior. Some development tools still emit deprecation notices; major migrations should be evaluated separately.
